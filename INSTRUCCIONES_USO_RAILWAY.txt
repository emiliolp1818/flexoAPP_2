  Fecha: 26 de Febrero 2026
================================================================================

📋 DOMINIOS QUE TIENES:

Frontend:  https://flexoapp-frontend.up.railway.app
Backend:   https://TU-DOMINIO-BACKEND.up.railway.app  (debes generarlo)

================================================================================
PASO 1: GENERAR DOMINIO PÚBLICO DEL BACKEND
================================================================================

1. Ve a Railway → Tu proyecto → Servicio Backend
2. Ve a Settings → Networking → Public Networking
3. Haz clic en "Generate Domain"
4. Ingresa el puerto: 8080 (o el que veas en los logs)
5. Railway generará un dominio como:
   https://flexoapp-backend-production-xxxx.up.railway.app

6. COPIA ESTE DOMINIO - Lo necesitas para el siguiente paso

================================================================================
PASO 2: ACTUALIZAR CONFIGURACIÓN DEL FRONTEND
================================================================================

Abre el archivo: Frontend/src/environments/environment.railway.ts

Reemplaza TODAS las ocurrencias de:
  TU-DOMINIO-BACKEND-RAILWAY.up.railway.app

Con tu dominio real (sin https://), ejemplo:
  flexoapp-backend-production-a1b2.up.railway.app

El archivo debería quedar así:

export const environment = {
  production: true,
  apiUrl: 'https://flexoapp-backend-production-a1b2.up.railway.app/api',
  socketUrl: 'https://flexoapp-backend-production-a1b2.up.railway.app',
  fallbackUrls: [
    'https://flexoapp-backend-production-a1b2.up.railway.app/api',
    'https://flexoapp-backend.onrender.com/api'
  ],
  // ... resto del archivo
};

================================================================================
PASO 3: COMPILAR EL FRONTEND PARA RAILWAY
================================================================================

Opción A - Usar desde tu computadora (LOCAL):
----------------------------------------------
1. Abre terminal en la carpeta Frontend
2. Ejecuta: npm run build:railway
3. El frontend se compilará apuntando al backend de Railway
4. Puedes servir localmente: npx serve -s dist/flexoapp
5. Abre: http://localhost:3000

Opción B - Desplegar frontend en Railway:
------------------------------------------
1. El frontend ya está desplegado en:
   https://flexoapp-frontend.up.railway.app

2. Pero necesitas actualizar las variables de entorno en Railway:
   - Ve al servicio Frontend en Railway
   - Ve a Variables
   - Agrega: API_URL = https://TU-DOMINIO-BACKEND.up.railway.app/api

3. Railway redesplegará automáticamente

================================================================================
PASO 4: VERIFICAR QUE FUNCIONA
================================================================================

1. Abre el navegador
2. Ve a: https://TU-DOMINIO-BACKEND.up.railway.app/health

   Deberías ver:
   {
     "status": "Healthy",
     "checks": {
       "database": "Healthy",
       "self": "Healthy"
     }
   }

3. Ve a: https://TU-DOMINIO-BACKEND.up.railway.app/swagger
   Deberías ver la documentación de la API

4. Abre el frontend:
   - Local: http://localhost:3000
   - Railway: https://flexoapp-frontend.up.railway.app

5. Intenta hacer login
6. Si funciona, ¡Railway está configurado correctamente! ✓

================================================================================
PASO 5: ACTUALIZAR CORS EN EL BACKEND (SI ES NECESARIO)
================================================================================

Si ves errores de CORS en la consola del navegador:

1. Abre: backend/Program.cs
2. Busca la sección "CORS CONFIGURATION"
3. Agrega tu dominio de frontend de Railway:

   policy.WithOrigins(
       // ... otros dominios ...
       "https://flexoapp-frontend.up.railway.app",  // ← Agregar esta línea
       "https://*.up.railway.app",
       // ... resto
   )

4. Haz commit y push:
   git add backend/Program.cs
   git commit -m "fix: Agregar dominio Railway frontend a CORS"
   git push origin render

5. Railway redesplegará automáticamente

================================================================================
COMPARACIÓN: LOCAL vs RAILWAY vs RENDER
================================================================================

LOCAL (tu computadora):
✓ Más rápido para desarrollo
✓ No consume créditos
✓ Ideal para pruebas
✗ Solo tú puedes acceder
✗ Debes tener la app corriendo

RAILWAY (pruebas):
✓ Accesible desde cualquier lugar
✓ Deploys rápidos (2-3 minutos)
✓ Bueno para pruebas con el equipo
✗ Consume créditos ($5/mes)
✗ Requiere tarjeta de crédito

RENDER (producción):
✓ Plan gratuito sin tarjeta
✓ Más estable para 24/7
✓ Mejor para producción final
✗ Deploys más lentos (5-10 min)
✗ Se duerme después de 15 min inactividad

================================================================================
SOLUCIÓN DE PROBLEMAS
================================================================================

Problema: "Cannot connect to backend"
Solución:
- Verifica que el backend esté corriendo en Railway
- Verifica que el dominio en environment.railway.ts sea correcto
- Verifica que el backend tenga dominio público (no .railway.internal)

Problema: "CORS error"
Solución:
- Agrega el dominio del frontend a CORS en backend/Program.cs
- Redespliega el backend

Problema: "Login no funciona"
Solución:
- Verifica que la base de datos MySQL esté corriendo en Railway
- Verifica las variables de entorno del backend (MYSQL_HOST, etc.)
- Revisa los logs del backend en Railway

Problema: "SignalR no conecta"
Solución:
- Verifica que el dominio en socketUrl sea correcto
- Verifica que WebSockets estén habilitados (lo están por defecto)
- Revisa la consola del navegador (F12) para ver errores
